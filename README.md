# Realm

轻量的 Realm TCP/UDP 端口转发管理脚本。支持规则增删改查、核心与脚本独立更新、服务自启、失败回滚和一键卸载，适用于 Debian、Ubuntu、Alpine 及带有服务管理器的 LXC / NAT VPS。

**管理脚本版本：v1.2.1**。脚本版本与 Realm 核心版本分别维护。

## 一键安装

使用 `root` 执行：

```sh
(curl -LfsS https://raw.githubusercontent.com/haoch1/realm/main/realm.sh -o /usr/local/bin/r || wget -q https://raw.githubusercontent.com/haoch1/realm/main/realm.sh -O /usr/local/bin/r) && chmod +x /usr/local/bin/r && r
```

首次下载需已有 curl 或 wget。命令将脚本下载到 `/usr/local/bin/r`，赋予执行权限并打开菜单。脚本自动识别包管理器、补齐依赖；Alpine 不需要提前安装 Bash。

添加第一条有效规则时自动获取 Realm 官方最新稳定版，根据架构选择安装包，校验 SHA256 摘要及程序实际版本，然后启动转发服务。没有规则时不会安装或启动 Realm。

以后使用以下命令打开管理菜单：

```sh
r
```

重复执行一键安装命令会更新管理脚本并保留已有规则；已安装的 Realm 核心通过菜单或 `r --update` 单独更新。

## 管理菜单

```text
端口转发管理（当前规则：2 条）
Realm 状态：运行中
Realm 版本：v2.9.6
管理脚本：v1.2.1

基础功能
[1] 添加转发规则
[2] 查看当前转发规则
[3] 修改转发规则
[4] 删除转发规则
[5] 清空所有转发规则

服务管理
[6] 启动 Realm
[7] 停止 Realm
[8] 重启 Realm

更新与卸载
[9] 更新 Realm
[10] 更新管理脚本
[11] 一键卸载

[0] 退出脚本
```

菜单标题会分别显示当前规则数量、Realm 状态、Realm 核心版本和管理脚本版本。Realm 状态分为“运行中”“已停止”和“未安装”；核心不存在时版本显示“未安装”，无法识别版本时显示“未知”。

添加规则时依次填写：本机监听端口、目标地址、目标端口、转发协议和备注名称。域名只填写主机名，不要包含 `http://`、`https://` 或路径。

| 选项 | 转发协议 | 示例 |
| --- | --- | --- |
| 1（默认） | TCP | `10001 → example.com:443` |
| 2 | UDP | `1053 → 1.1.1.1:53` |
| 3 | TCP+UDP | 同一端口同时转发两种协议 |

新规则监听 `0.0.0.0`，允许的端口范围是 `1–65535`。同一端口可以分别建立 TCP 和 UDP 规则；协议发生重叠或端口已被其他程序占用时，脚本会拒绝保存。

保存规则后会自动启动 Realm 并设置开机自启，修改时回车保留原值。删除最后一条规则或清空全部规则后，服务停止并取消自启。应用规则会重启服务，现有连接可能中断；启动或监听检查失败时尝试恢复原配置和服务状态。

服务管理选项只控制 Realm 服务：启动会启动服务并开启开机自启；停止会停止服务并取消开机自启；重启会重启服务并恢复开机自启。启动和重启都要求至少存在一条转发规则。

## 域名解析

目标地址支持域名、IPv4 和 IPv6，保存前检查地址格式，不要求域名当场解析成功。IPv6 可以填写 `2001:db8::1` 或 `[2001:db8::1]`。

添加或修改规则时，输入域名后会通过系统 `getent` 查询当前解析结果，优先显示 IPv4，其次 IPv6。例如：

```text
  [成功] 域名已解析: example.com -> 192.0.2.1 (ipv4)
```

查询最多等待 5 秒，解析失败会显示提示，仍可继续填写并保存。此结果仅用于当次反馈，规则中仍保存域名。

域名原样写入配置，由 Realm 内置解析器处理，Linux 默认读取系统 `/etc/resolv.conf`。解析缓存受 DNS TTL 和 Realm 配置影响，没有脚本定时轮询任务。缓存过期后，后续查询会重新解析；已经建立的 TCP 连接不会自动迁移到新 IP。

## 交互与单实例

添加、修改规则的任意输入步骤均可输入 `q` 取消并直接返回菜单，规则选择中的 `0` 或空输入继续表示取消；未提交的输入不会保存。查看结果和操作完成后按回车返回菜单，输入 `Ctrl+D` 会正常退出。任何交互界面按 `Ctrl+C` 都会换行后立即退出整个管理脚本并返回状态码 `130`，不会再次显示菜单。更新或应用配置期间中断时，脚本会先清理临时文件并按原有逻辑恢复核心、配置和服务状态。正常结束可选择 `[0] 退出脚本`。

脚本通过文件锁限制同时运行的管理实例。旧窗口丢失时，重新运行 `r` 会核对锁持有者，通知旧管理脚本退出，最多等待 5 秒接管。输入操作直接在主进程执行，服务命令不继承管理锁。

如果旧脚本正在下载或执行配置事务，会保留锁直到操作结束或完成回滚；超时后稍候重试，不要手动删除锁文件。关闭管理菜单不会停止转发服务。

## 系统与网络环境

| 系统 | 服务管理 |
| --- | --- |
| Debian / Ubuntu | systemd |
| Alpine | OpenRC |
| RHEL / Rocky Linux / AlmaLinux | systemd |

支持 `x86_64`、`ARM64` 和 `ARMv7` 硬浮点架构。LXC 需要运行 systemd 或 OpenRC；Realm 用户态转发不需要 TUN、`NET_ADMIN` 或内核 IP 转发权限。

NAT VPS 应填写容器内部端口。例如服务商提供 `公网:30001 → 容器:10001`，本机监听端口填写 `10001`，客户端连接公网端口 `30001`。防火墙和上游端口映射必须包含所选协议；TCP+UDP 需要同时映射两种协议。脚本不会创建服务商或宿主机的公网端口映射。

## 更新

更新 Realm 核心：

```sh
r --update
```

也可以在菜单选择 `[9] 更新 Realm`。每次查询官方最新稳定版，更新前备份旧核心；校验失败不替换，运行检查失败时尝试恢复旧核心。已是最新版时不会重启服务。

更新管理脚本：

```sh
r --update-script
```

也可以在菜单选择 `[10] 更新管理脚本`。界面显示当前版本与最新版本；检查脚本格式、版本号和 Bash 语法后原子替换 `/usr/local/bin/r`。检查成功后按回车重新加载磁盘上的脚本，包括提示已是最新版的情况。命令行更新成功后直接打开菜单；更新管理脚本不会重启 Realm 服务。

查看管理脚本版本：

```sh
r --version
```

## 卸载

在菜单选择 `[11] 一键卸载`，或者执行：

```sh
r --uninstall
```

确认后停止服务、取消开机自启，删除服务文件、Realm 核心、全部规则、备份、独立日志、管理锁和 `r` 命令。也会清理异常退出留下的下载、更新临时文件，以及服务文件缺失后残留的自启链接。

停止服务或取消自启失败时不会继续删除安装文件。Bash、curl 等共用依赖及系统共享日志保留。

## 文件与日志

- 管理脚本：`/usr/local/bin/r`
- Realm 核心：`/root/realm/realm`
- 转发配置：`/root/realm/config.json`
- 最近备份：对应文件的 `.bak`

| 操作 | systemd | OpenRC |
| --- | --- | --- |
| 查看状态 | `systemctl status realm` | `rc-service realm status` |
| 查看日志 | `journalctl -u realm -n 50 --no-pager` | `tail -n 50 /var/log/realm.log` |
